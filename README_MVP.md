# Граф денег — MVP

Локальный инструмент для первичного анализа обезличенной сети переводов. Он помогает AML-аналитику быстрее перейти от известных seed-клиентов к возможным точкам консолидации, транзита и распределения средств, а также выбрать узлы для приоритетной проверки.

**Результаты — структурные признаки и гипотезы для проверки, а не вывод о виновности.** В данных нет персональных атрибутов и размеченных ролей, поэтому роли и рейтинг не являются доказанной классификацией.

## Какую проблему решает проект

По условию кейса аналитик получает список известных клиентов и ограниченную выгрузку их исходящих переводов. Ручное прохождение связей занимает время, оставляет большую часть сети незаметной и затрудняет выбор следующего клиента для проверки.

MVP автоматизирует первичную обработку графа: считает признаки входящих и исходящих потоков, присваивает каждому узлу объяснимую эвристическую роль, выделяет сообщества, формирует ранжированный список и даёт интерфейс для поиска узла и просмотра его связей. Это сокращает ручную подготовку структуры и даёт аналитику воспроизводимую отправную точку для проверки.

## Решена ли проблема из ТЗ?

**Основной сценарий MVP реализован:** из локальных Parquet-файлов можно получить три аналитические CSV-выгрузки и открыть Streamlit-панель. На имеющемся датасете в артефактах есть 2 248 узлов с ролью, оценкой, кластером и непустым объяснением; 89 кластеров; ранжированный top-20. Пайплайн строит роли и рейтинг по метрикам графа, а интерфейс позволяет искать gid, смотреть карточку и направленные соседние потоки, а также изучать выбранный кластер.

По обязательным пунктам ТЗ:

| Пункт | Состояние MVP |
| --- | --- |
| Воспроизводимый запуск от трёх Parquet до CSV | Реализован командой `python -m src.pipeline`; вход и выход локальные. В README исходного проекта указано контрольное время около 10,57 с на использованном ноутбуке, меньше лимита 5 минут. |
| Роль, score и evidence у каждого узла | Реализовано для всех 2 248 узлов в `output/nodes_roles.csv`; пайплайн проверяет заполненность и диапазоны score. |
| Объяснимые критерии ролей | Реализованы как детерминированные правила по степеням, суммам, seed и depth; пороги приведены ниже. |
| Кластеризация с описанием | Реализована Louvain-кластеризация на неориентированном графе с весом суммы переводов; выгружаются размер, seed, внутренний оборот, ключевые gid и текстовая гипотеза. |
| Приоритетный список и экран просмотра | Реализованы top-20 с обоснованием и поиск gid в Streamlit; доступны направленная схема окрестности/потока, роли, путь от seed при наличии и карточка кластера. |

Таким образом, MVP **закрывает основную аналитическую задачу и обязательный функциональный сценарий кейса на предоставленном срезе**. Это не полноценная AML-система: она не подтверждает преступную роль клиента и не заменяет анализ первичных операций. Также в текущем интерфейсе визуализируется выбранная окрестность/кластер с ограничением числа рёбер для читаемости, а не весь граф сразу.

## Требования

- Python 3.10 или новее.
- Файлы `data/nodes.parquet`, `data/edges.parquet`, `data/transactions.parquet`.
- Установка зависимостей требует доступа к источнику Python-пакетов.

## Запуск

Из корневой папки проекта выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.pipeline
streamlit run app.py
```

Откройте [http://localhost:8501](http://localhost:8501). Остановить панель можно сочетанием `Ctrl+C` в терминале.

Пайплайн читает три файла из `data/` и создаёт/перезаписывает:

- `output/nodes_roles.csv` — одна строка на каждый узел;
- `output/clusters.csv` — сводка по сообществам;
- `output/top_nodes.csv` — первые 20 узлов по приоритету.

Чтобы пересчитать данные из другого расположения, используйте параметры:

```bash
python -m src.pipeline --data-dir /path/to/data --output-dir /path/to/output
```

Панель читает стандартные `data/` и `output/` относительно корня проекта. Если CSV ещё не созданы, сначала запустите пайплайн.

## Как работает аналитика

Пайплайн объединяет список узлов, агрегированные направленные рёбра и отдельные транзакции. По рёбрам считает входящие/исходящие степени и суммы, по транзакциям — простые временные признаки. Затем каждому узлу назначает одну роль. Правила проверяются в таком порядке, поэтому при одновременном совпадении применяется первая подходящая роль.

| Роль | Правило |
| --- | --- |
| `consolidator` | Не seed; не менее 2 входящих рёбер; входящая сумма не меньше 1,25 исходящей. Seed исключены из этого правила, так как их входящие потоки неполны. |
| `distributor` | Не менее 2 исходящих рёбер; исходящая сумма не меньше 1,25 входящей. |
| `coordinator` | Не менее 4 инцидентных рёбер, причём есть хотя бы одно входящее и одно исходящее. |
| `transit` | Есть ребро в обоих направлениях; отношение исходящей суммы к входящей от 0,5 до 2 (либо входящая сумма равна нулю). |
| `terminal` | Есть входящее, нет исходящих; глубина меньше 4 или неизвестна. Узел на глубине 4 не объявляется конечным только из-за отсутствия исходящих: это может быть обрыв выгрузки. |
| `peripheral` | Все остальные случаи, включая узлы без рёбер и узлы, обрезанные на depth 4. |

`role_score` — выраженность структурных признаков по формуле для соответствующей роли, ограниченная диапазоном 0–1. Это **не вероятность** и не модель, обученная на подтверждённых примерах. В `evidence` записываются роль, числа входящих/исходящих рёбер и суммы, глубина, признак seed; при наличии добавляются некоторые дневные и повторяющиеся транзакционные сигналы.

`priority_score` — взвешенная сумма: `0.35 × role_score + 0.25 × нормированный log(1 + оборот) + 0.20 × нормированная степень + 0.20 × ограниченное отношение исходящей суммы к входящей`. Каждый компонент приводится к диапазону 0–1. В top-листе к этим признакам добавляется краткое объяснение и кратчайший найденный путь от seed либо сообщение, что путь в выгрузке не найден.

Кластеры рассчитываются алгоритмом Louvain на неориентированном представлении графа, с весом ребра `sum_kzt` и фиксированным seed 42. Направление потоков сохраняется для метрик и визуализации. Текст `hypothesis` описывает структуру кластера и является подсказкой для анализа, а не установленным назначением группы.

## Интерфейс

Панель показывает сводные показатели, top-20, распределение ролей по глубине и сводку выбранного кластера. Поиск работает по любому `gid` из выгрузки, в том числе по узлам без рёбер. Карточка узла содержит роль, score, evidence, приоритет и кластер. Визуализация показывает направления связей, суммы, цвета ролей и путь от seed, когда он найден. Для читаемости число отображаемых рёбер ограничено; полные данные остаются в Parquet и CSV.

## Ограничения

- Граф построен только по исходящим переводам seed на глубину до четырёх переходов; исходящие связи за границей обхода не видны.
- Входящие суммы seed неполны. Порог выгрузки исключает операции меньше 5 000 KZT.
- В данных нет атрибутов клиента и подтверждённых меток ролей. Поэтому нельзя оценить точность классификации как supervised-модели.
- Приоритет — относительный рейтинг внутри данного набора, а не оценка риска или доказательство нарушения.
- Кластеры показывают структурную близость в выбранном срезе; автоматически сгенерированная гипотеза требует проверки операций и внешнего контекста, который в датасете отсутствует.
- Обработка миллиона узлов потребует иного режима хранения и выдачи графа: индексированного хранилища рёбер/признаков, пакетного расчёта и серверной загрузки ограниченной окрестности вместо полного графа в интерфейсе. Текущая реализация предназначена для датасета кейса.
