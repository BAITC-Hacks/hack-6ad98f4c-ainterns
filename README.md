# Граф денег

Локальная панель для изучения графа переводов и аналитических сигналов. Роли и приоритеты — это **признаки и гипотезы для проверки**; сами по себе они не доказывают виновность.

## Установка и запуск

Требуется Python 3.10+. Команды выполняются из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python -m src.pipeline          # пересчёт CSV из трёх parquet
streamlit run app.py            # открыть интерфейс отдельно
```

Входы: `data/nodes.parquet`, `data/edges.parquet`, `data/transactions.parquet`. Пайплайн сохраняет `output/nodes_roles.csv`, `output/clusters.csv`, `output/top_nodes.csv`. Панель рассчитана на запуск из корня, но пути к файлам разрешает относительно расположения `src/app.py`.

По проверке backend на текущем датасете расчёт обрабатывает 2 248 узлов, создаёт 89 кластеров и top-20; проверочное время — около 10,57 с на использованном ноутбуке. Конкретное время зависит от оборудования.

## Интерфейс

- Топ-лист показывает ранг, gid, роль, priority score и объяснение `why`, включая seed и длину направленного пути, если путь есть.
- Поиск принимает любой `gid` из `nodes_roles.csv`; карточка показывает роль, `role_score`, `priority_score`, кластер и `evidence`.
- Направленная окрестность читается из `edges.parquet`: стрелка идёт от `src` к `dst`; роль задаёт цвет, выбранный узел выделен. Для читаемости на графе остаются до 80 крупнейших по сумме соседних рёбер.
- Таблицы показывают до восьми входящих и исходящих соседей с суммой переводов и числом транзакций, когда оно присутствует в parquet.
- Карточка кластера показывает его гипотезу и ключевые `top_gids`. Это ключевые gid, а не полный список членов кластера.
- Если входы/выходы отсутствуют или схема не совпадает, интерфейс показывает сообщение с ожидаемыми путями и колонками.

Фиксированные колонки: `nodes_roles.csv`: `gid, role, role_score, cluster_id, priority_score, evidence`; `clusters.csv`: `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis`; `top_nodes.csv`: `rank, gid, role, priority_score, why`. В `top_gids` числовые gid разделены запятыми в одной CSV-ячейке, например `"1024,2048,4096"`.

## Аналитическая логика

### Роли

Каждому узлу присваивается ровно одна эвристическая роль. Правила применяются в порядке приоритета **consolidator → distributor → coordinator → transit → terminal → peripheral**; при совпадении побеждает первое подходящее правило.

| Роль | Формальное правило |
| --- | --- |
| `consolidator` | Не seed; не менее 2 входящих рёбер; входящая сумма не меньше 1,25× исходящей. |
| `distributor` | Не менее 2 исходящих рёбер; исходящая сумма не меньше 1,25× входящей. |
| `coordinator` | Не менее 4 инцидентных рёбер и хотя бы одно ребро в каждом направлении. |
| `transit` | Хотя бы одно входящее и исходящее ребро; исходящая/входящая сумма в диапазоне 0,5–2 (либо входящая сумма нулевая). |
| `terminal` | Есть входящее, нет исходящих рёбер, а depth меньше 4 или неизвестен. |
| `peripheral` | Все остальные случаи, включая изолированные узлы и обрыв на depth=4. |

`role_score` — ограниченная диапазоном [0, 1] выраженность структурных признаков роли, не обученная вероятность. В порядке ролей применяются формулы: `consolidator = min(in_degree/4, in_amount/(2.5×max(out_amount, ε)))`; `distributor = min(out_degree/4, out_amount/(2.5×max(in_amount, ε)))`; `coordinator = min((in_degree+out_degree)/8, 1)`; `transit = min(1, 0.5+min(in_degree,out_degree)/4)`; `terminal = min(1, 0.5+in_degree/4)`; `peripheral = 0.5` для узла без рёбер, иначе `0.35`. Результат ограничивается [0, 1]. Для seed неполные входящие потоки, поэтому они исключены из правила consolidator. Нет исходящих у узла на depth=4 из-за обрыва обхода само по себе не означает terminal.

В `evidence` могут также упоминаться дополнительные транзакционные сигналы: число дней с переводами как минимум от двух отправителей и максимум уникальных отправителей за день (при максимуме от 3); число направленных пар с двумя или более положительными суммами в пределах ±10% от медианы; число исходящих переводов на следующий календарный день после входящего и их доля среди исходящих. Даты имеют точность до дня, поэтому быстрый транзит — консервативный временной признак, а не прослеживание тех же денег. Повтор суммы не трактуется как дробление.

### Приоритет и кластеры

`priority_score` — взвешенная сумма, все части приведены к [0, 1]:

`0.35 × role_score + 0.25 × norm(log1p(turnover)) + 0.20 × norm(in_degree + out_degree) + 0.20 × clip(pass_ratio, 0, 1)`.

`norm` делит положительные значения на максимум по датасету; `pass_ratio = out_amount / in_amount`, при нулевой входящей сумме используется 0. Кластеры строятся Louvain на неориентированном графе с весом `sum_kzt` и фиксированным seed 42. Направление рёбер при этом сохраняется в окрестности интерфейса и в поиске пути от seed.

## Ограничения и интерпретация

- Датасет получен обходом глубиной до четырёх переходов; исходящие связи после обрыва могут быть не видны.
- Граф собран по исходящим переводам seed, поэтому входящие потоки seed неполны.
- В выборку входят отдельные переводы от 5 000 KZT; меньшие операции отсутствуют.
- Нет ground truth, по которому можно было бы оценить точность эвристических ролей или ранжирования.
- Изучайте исходные операции и контекст. Называйте выводы признаками и гипотезами для проверки.

В стресс-сценарии backend после удаления пяти верхних узлов приоритета получил 389 слабосвязных компонент (+354 относительно исходного графа), а 534 узла потеряли путь от seed. Это структурная проверка на конкретном снимке, не прогноз реального вмешательства.

1. **0:00–1:00:** запустить `python -m src.pipeline`, показать завершение расчёта и три CSV в `output/`.
2. **1:00–2:00:** запустить `streamlit run app.py`, показать top-20 и `why`.
3. **2:00–3:00:** ввести согласованный с жюри gid, показать стрелки и ближайшие связи.
4. **3:00–4:30:** разобрать роль, scores, evidence и входящие/исходящие суммы у двух узлов; отметить ограничения seed/depth.
5. **4:30–5:00:** показать гипотезу и ключевые узлы кластера; сформулировать результат как гипотезу для проверки.

## Переход к графу примерно в 1 млн узлов

Не загружать весь граф в браузер. Хранить рёбра и признаки с индексом по gid, выполнять серверный запрос окрестности с лимитом/пагинацией, считать метрики и сообщества пакетно, кэшировать повторные запросы и отправлять в интерфейс только выбранную окрестность.

Корневые `app.py` и `streamlit_app.py` — короткие точки входа к фронтенду в `src/app.py`. Отдельные `package.json` и `index.html` здесь не используются: UI работает как Python-приложение Streamlit.

Схема обработки приведена в [solution-schema.md](solution-schema.md).
